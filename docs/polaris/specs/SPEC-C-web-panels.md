## Objective

A Polaris page in the web client (and therefore desktop) that shows and controls what
`polarisd` owns: runs across both backends, ports, tunnels, simulators, and the
tmux → T3 migration. Data comes from `polarisd` through the server's authenticated
proxy at `/api/polaris/proxy/v0/*` (see `apps/server/src/polaris/Proxy.ts`). The
`polarisd` API is documented by its route table and handlers in the sibling checkout
`~/src/zpv/polaris-t3/internal/polaris/server.go` (read-only reference; entity shapes in
`model.go`, T3 additions in `t3.go`).

## Data layer (`apps/web/src/polaris/api.ts`, `state.ts`)

- HTTP: find how existing web code makes authenticated HTTP requests to an environment
  (for example attachment upload, assets, `DeviceHubProxy` consumers in the Device
  panel) and use the same helper so it works for the local environment, remote
  environments and the desktop app. The page targets one environment at a time: the
  primary/active one by default, with the same environment picker pattern the Usage page
  header uses when more than one environment is connected.
- Availability: `GET /api/polaris/proxy/v0/health`. Not OK (404, 502, network) means
  Polaris is unavailable in that environment: the sidebar button and palette items do
  not render, and the route shows an empty state explaining that this environment has no
  Polaris daemon.
- Live updates: read `GET /api/polaris/proxy/v0/events/stream?after=<id>` with `fetch`
  and a streaming reader (the stream uses named SSE events and ignores `Last-Event-ID`,
  so `EventSource` is unsuitable). Parse frames, de-duplicate on event id, reconnect
  with capped jittered backoff resuming from the last id. On relevant event types
  refetch the affected collection (debounced 250 ms). Also refetch everything every 30 s
  and on window focus. Only stream while the page is open.
- Mutations surface errors from `{error}`, `{ok:false, reason}` and `{stderr}` bodies.
  Never auto-retry a mutation.

## Page

Route `/polaris`, registered like `/usage` (`apps/web/src/routes/_chat.usage.tsx`).
Study `components/usage/UsagePage.tsx` and build with the same shell: the same sheet
over the chat, the same header row (breadcrumb on the left, segmented control, refresh
and close on the right), the same section and card treatment, the same Escape-to-close
and close-button behaviour. Compose its building blocks; if they are private to the
Usage page, mirror their classes in Polaris-owned components rather than editing them.

Header: `Polaris / <environment label>`; segmented control `Runs · Resources · Devices`;
the active tab is URL search state (`?tab=`), default `runs`.

### Runs tab

- Toolbar: search field (matches run name, project, branch, run id), an `Active only`
  switch (default on: hides runs with status stopped/failed), and on the right a
  `Move to T3…` button that opens the migration dialog (below) when any tmux-backed
  agent run exists.
- Runs grouped by project (project name as a section heading with its run count; runs
  without a project under `No project`), most recent activity first within a group.
  Agent runs first, then a `Services` subgroup for `shell` runs (Metro, dev servers).
- Row (40 px, one line, truncating): state dot + run name; agent icon (reuse the
  provider icons for Claude/Codex; a terminal icon for shell); backend label `T3` or
  `tmux` in muted text; model; branch; relative last-activity time (tabular numbers);
  a Discord icon link when the run has a Discord bridge (`GET /v0/discord/bridges`,
  link `https://discord.com/channels/<guildId>/<threadId>`).
- State dot: working = accent dot with a slow pulse (respect `prefers-reduced-motion`);
  waiting = amber; idle = muted; failed = red; stopped = hollow ring. For T3 runs use
  `turnState`; for tmux runs derive from status only (running → idle dot, labelled
  `running`). Every dot has a text label for screen readers and a tooltip.
- Row actions (icon buttons revealed on hover and focus, always present in a `⋯` menu
  for touch): `Open thread` (T3 runs; navigates to the thread route using
  `t3ThreadId`, closing the page), `Stop` (confirm), `Resume` (stopped runs),
  `Move to T3` (tmux agent runs; opens the migration dialog scoped to that run),
  `Send link to phone` (T3 runs; `POST /v0/notifications/phone` with `kind: "link"`,
  the thread link as `url`), `Copy run ID`.
- Shell runs expand in place (chevron) to a `Peek`: the plain-text snapshot
  (`GET /v0/runs/{id}/snapshot?lines=120`) in a monospace, scrollable, 16-line block
  pinned to the bottom, refreshed every 2 s while expanded, with a one-line input below
  that posts to `/v0/runs/{id}/input` on Enter. Sending shows pending state and keeps
  the text on failure.

### Migration dialog

- Opens with a dry run (`POST /v0/t3/migrate` with `dryRun: true`, plus `runIds` when
  scoped to one run). Shows the rule in one sentence ("Runs active in the last 14 days,
  plus the 5 most recent per project"), then counts: will move, deferred, skipped.
- A list grouped by project: run name, agent, and for deferred/skipped rows the reason in
  plain words (`live` → "running in tmux"; `working` → "mid-turn"; `no-session` → "no
  saved session"; `worktree-missing` → "worktree deleted"; `liveness-unknown` → "tmux
  unreachable").
- A checkbox `Also move idle runs that are open in tmux (closes their terminal)`; toggling
  it re-runs the dry run with `includeLive`.
- Primary button `Move N runs` (disabled at 0). On confirm, `dryRun: false`; show
  per-run results as they return (the call is a single request; show a progress state,
  then the result list with links to the new threads and failures with their reason).
  The dialog cannot be dismissed by Escape or backdrop while the request is in flight.

### Resources tab

- **Ports** card: port (tabular, monospace), purpose, owning run (name, links to its
  row), age, `Release` (confirm). Released leases are not listed. Empty state: "No
  ports reserved."
- **Tunnels** card: provider, target port, public URL (click to open, copy button),
  status, `Stop` (confirm). Empty state: "No tunnels."

### Devices tab

- **Simulators** card: one row per lease: device name, runtime, owning run, age; when a
  stream exists, `Open viewer` (the stream's `viewUrl`, new tab) and `Stop stream`;
  `Release` (confirm; warns that it stops the stream). Data from
  `/v0/devices/simulators/leases` and `/v0/devices/simulator-streams`. Empty state:
  "No simulators reserved."

### Shared behaviour

- Loading: skeleton rows sized like real rows; no layout shift when data arrives.
- polarisd unreachable after it was available: a banner above the content with the
  reason and `Retry`; stale data stays visible, dimmed.
- Confirmations use the existing confirm dialog (`apps/web/src/confirmDialog.ts`);
  results use the existing toast.
- Keyboard: tabs are arrow-navigable; rows are reachable by Tab; actions have
  `aria-label`s; focus returns to the trigger when a dialog closes.
- Light and dark themes; no gradients, no emoji, no coloured pills; colour only on the
  state dot and destructive buttons.
- Below 768 px wide: rows wrap to two lines (name and state on the first, metadata on
  the second); actions collapse to the `⋯` menu; the segmented control stays one row.

### Entry points

- Sidebar footer: an icon button with tooltip `Polaris`, shown only when available.
- Command palette: `Open Polaris`, `Polaris: Move runs to T3…`, `Polaris: Ports and
  tunnels` (opens the Resources tab), shown only when available.
